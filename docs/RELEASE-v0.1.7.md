# Tunnel Studio v0.1.7 · KANO 开机自启修复

v0.1.6 只写入 Magisk service.d，未注册旧 WireGuard 插件使用的 KANO 自启脚本；启动又只等待 25 秒尝试一次并丢弃输出。v0.1.7 注册 `/sdcard/ufi_tools_boot.sh` 中带所有者标记的一行，调用私有启动脚本，保留其他服务内容。已有 Magisk service.d 时保留备用入口，共用启动任务锁避免重复创建隧道。

自启会等待 Android 完成开机、热点接口与 IPv4 地址、隧道端点 DNS 和外部路由就绪。检查间隔为 10 秒，等待重试预算 5 分钟；正在进行的有界检查或启动可能增加结束耗时。管理锁只在每次检查/启动期间持有，等待期间可以刷新或关闭自启。手动停止会取消本次开机的后续重试，下一次开机仍按自启设置执行。

连接概览显示本次开机的等待、完成、失败、超时，避免把脚本存在当作启动成功。诊断增加 `bootInfo`，私有 `runtime/boot-status.json` 保存最近最多 32 次检查，启动脚本记录固定的执行/摘要失败信息，不记录配置密钥。已有运行隧道不再重复启动；资源过时、接口冲突或本次开机的未完成路由事务会停止重试，不削弱原有恢复保护。

## 更新

停止隧道，替换 KANO 中的 JS，保存刷新，点击“安装 / 更新”，然后在连接概览重新点一次自启“开启”。原设备配置保留，原本启用的自启会在更新时迁移。

**KANO 的自启脚本需要启用 KANO 高级功能。** 旧 WireGuard 插件的自启行和其他服务均保留。不要同时开启两个插件接管相同流量。

## 验证范围

通过 Go 测试、静态检查与浏览器自启状态回归，交叉编译 Android ARM64。Android x86_64 模拟器执行了真实 shell 启动和摘要拒绝、共享存储文件读写、符号链接拒绝、升级/回滚脚本更新、延迟就绪/有限重试、事务保护测试。共享存储测试发现 FUSE 不支持文件 flock，已在不支持时保留私有管理锁与写前内容校对。

未连接到 U30 Air，未在该设备进行真实断电重启测试。v0.1.6 网络处理保持不变；用户此前已反馈联网恢复正常，仍不承诺长期稳定性或吞吐。
