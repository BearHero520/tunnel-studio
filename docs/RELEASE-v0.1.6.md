# Tunnel Studio v0.1.6 · TCP 双向处理与实际联网检测

v0.1.5 只限制热点客户端发往隧道的 TCP SYN 所通告的 MSS，遗漏了从隧道返回热点的 SYN/SYN-ACK。v0.1.6 为“仅热点”和“本机 + 热点”补上返回方向的处理，覆盖 IPv4 与启用代理的 IPv6；返回包不要求具有出站代理标记。两侧依据配置的 MTU 限制 MSS，停止时按事务记录撤销新增规则。“仅本机”不增加热点规则。

## 详细检测

“只读诊断”页新增“检测联网”，需运行支持本功能的设备后端和自动代理模式：

- 通过配置中的第一个 IPv4 DNS 分别记录 UDP A、TCP A、UDP AAAA 查询的结果与耗时，不使用公共 DNS 回退。
- 对 ChatGPT、登录服务、百度和 Google 的公开入口记录 TCP、TLS 证书验证、HTTP 响应及耗时，对照 HTTP/1.1 和服务支持时的 HTTP/2。
- 可填写内网 HTTP 服务的 IPv4:端口，执行无凭据的 GET /，交替使用普通请求和 8192 字节检测头，最多五次。记录状态、响应字节数、耗时和失败阶段，不保存响应正文，不调用模型 API。
- 检测前、后及采样期间记录隧道状态、流量、握手。检测套接字强制绑定 kts0 和专属路由标记，不能静默退回移动网络直连。

检测从路由器本机发起，不能替代热点电脑的实际流量测试。网络检测预算为 20 秒，后台状态读取可能增加数秒耗时；不是长时间稳定性、已登录 Codex 会话或流式模型响应测试。HTTP 401/403 说明收到了 HTTP 响应，不表示应用授权成功。

## 更新与验证

停止 Tunnel Studio，替换 KANO 中的旧 JS，保存并刷新，再点击“安装 / 更新”。设备已保存配置会保留；需要更新后端才能应用新规则和检测功能。

已通过 Go 测试、静态检查、配置重载、浏览器流程和检测输入回归。构建了 Android ARM64 资源。当前无法通过 ADB 连接 U30 Air，本版未完成该设备上的实际 Codex 对话验证。

**双向 MSS 遗漏已修复，但尚未证实它就是用户报告的 Codex 断线原因。本版为联调预览，不承诺已解决断线或吞吐问题。** 旧版 WireGuard 使用不同后端和接管范围，不能仅凭普通网页正常就推断内网模型服务的连接正常。
